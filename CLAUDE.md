## Running

THz time-domain spectroscopy (THz-TDS) evaluation tool with an auto-generated PySide6 GUI. There is no build step, test suite or linter config; dependencies are in `requirements.txt`.

PySide6 is pinned below 6.12 for Python < 3.12: 6.12.0 releases one reference too many on every `Signal.emit()`, so the refcount of `True` / `False` / `None` runs down and Python 3.11 aborts after a while ("Fatal Python error: bool_dealloc"; immortal objects from Python 3.12 on). The project `venv` uses Python 3.11.

```
python load_with_ui.py eval_scripts/test_script.py
```

Run from the repository root: settings are loaded from / saved to `config/<script stem>.json` relative to the working directory (e.g. `config/test_script.json`). `load_with_ui.py` executes the given script, takes its `AppRoot` class, builds the UI from it and runs the Qt event loop.

`cli.py` runs the same components without the GUI (hidden Qt app, same config file, `--set path=value` overrides that aren't saved unless `--save-settings`), e.g. `python cli.py qspace --select sample1_2 --out results.csv`; `python cli.py get <dotted.path>` lists settings.

Most other files in `eval_scripts/` (`from dataset import ...`, `dataset_eval`) use an older, removed API and don't run against the current `common/` package; `eval_scripts/test_script.py` is the current entry script.

## Architecture

### Component / trait framework → auto UI
- Everything user-facing is a `ComponentBase` (`common/components.py`, a traitlets `HasTraits`). `qtui/autoui.py` walks the component tree and generates widgets from trait metadata, so adding a setting or button means adding a trait or `@action` method — no UI code.
- Trait `.tag(...)` / constructor metadata read by the UI: `name`, `group`, `priority` (ordering), `help`, `toggle` (a `ComponentToggle` trait name that shows/hides a sub-component), `en_save=False` (don't persist), `significant_figures`, `preferred_units`, `width`, `fullwidth`, `combine`, `disable_label`.
- Groups appear in the order of their lowest `priority` entry (then trait type and name), so give each group of a component its own priority range.
- Trait observers update widgets, so traits must only be set in the GUI thread. Code running in the evaluation threads goes through a Qt signal (queued to the GUI thread) connected to `set_trait`, e.g. `QSpaceEval.task_status_carrier`, `RemoteOpt._status_signal`, `MeasurementSelection._set_trait_in_gui_thread` (`direct_match` from `get_matching_refs`, which the image / selection evaluations call).
- `@action(name, group=..., priority=...)` turns a method into a button. Pressing its button logs a header record (`extra={"action_header": True}`, in `autoui.create_action`, so actions called from code don't) that `load_with_ui.HTMLFormatter` renders as a highlighted separator line in the message panel. Modules typically rebind it with `partial(action, check_init=True, rc_params=mpl_style_params)` so actions are blocked until the dataset cache is initialized and run inside the matplotlib style context.
- Custom traits in `common/traits.py`: `Quantity` (pint quantity), `ValueRange` (2-element range), `Path`, `PlotFigure`, multi-path selection. `Q_` is the pint quantity from `common/units.py`.
- Persistence: `Settings` (`common/settings.py`, subclass of `AppSettings` in `common/default_appsettings.py`) saves/loads every component's traits on `__exit__`/`__enter__` of the component context. Quantities are stored as magnitudes only, so the unit of the trait default is the implied unit — changing a default's unit silently reinterprets saved configs. Enums are stored by member name. With `AppSettings.save_settings_on_exit` off, `save_configuration` writes nothing except that flag (so it stays off on the next start). The settings file is `Settings.config_path`: `config/<script stem>.json`, or the file chosen with "Load settings file" / "Save settings as" (remembered in `config/<script stem>.last_settings_file`; `Settings.settings_file_override` / `cli.py --config` take precedence). `Settings._components` lists every component that called `load_configuration`; loading another file (`load_configuration(..., reset_missing=True)`) and "Reset all settings" go through it. `reset_to_defaults(instance, group=...)` (also the right-click menu of each group box, `autoui.add_reset_menu`) only resets saved, writable traits of the `resettable_traits` types.
- `default_appsettings.py` holds the shared enums (`QuantityEnum`, `Domain`, `ColorMaps`, ...) and the global option groups (`pp_opt` preprocessing, `eval_opt`, `plot_opt`, `shgo_options`, `component_toggle`). Components reach them via `self.settings`. `eval_opt` has the sub-components (sub-tabs) `q_value` (`QValueOpt`), `spline_fit` (`SplineFitOpt`), `transmission_sim` (`TransmissionSimOpt`) and `image_eval` (`ImageEvalOpt`, tuning of the image evaluation, read via `QSpaceImageEval.opt`; moved from `QSpaceEval.image_eval`, `migrate_config` copies those entries from the QSpaceEval section of the config); `pp_opt` has the sub-component `window` (`WindowOpt`: window options and parameters). `common.settings.migrate_config` (`_split_option_groups`) moves entries of configs saved before that (flat in `eval_opt` / `pp_opt`) to them on load. `ComponentBase.override` raises for names that aren't traits of that component (e.g. `pp_opt.window.override(window_enabled=True)`, not `pp_opt.override(...)`). When moving a setting, extend such a migration, otherwise saved values silently reset to the default.

### Data flow
- `DataSet` (`common/dataset.py`) owns the measurements, a `DatasetCache` of raw time-domain data (built in a background thread; `is_initialized` gates actions), the `MeasurementSelection` (`common/measurement_selection.py`: reference/sample classification, point/line/area selection, selection queue; `auto_queue` groups samples by consecutive run, position or file name (`sample_grouping`, `group_name_pattern`) and pairs references per block or per measurement (`queue_ref_pairing`)), and all derived quantities. `quantity_func(QuantityEnum, ...)` maps a `QuantityEnum` to a vectorized method that returns per-measurement arrays (1D per measurement or 2D measurement × frequency).
- Parsing (`DataSet._parse_measurements`) runs again after a running parse only if the path or the file format changed meanwhile (`_parse_key`): a second parse makes new `Measurement` objects, which loses results keyed by them (e.g. `QSpaceImageEval._meas_pixel`).
- Measurement files: `DataSet._data_files` (`file_glob`), each parsed by `Measurement(path, FileNameFormat)` (`common/measurements.py`; `DataSet.file_name_parser()` from `file_name_format` / `time_format`). An empty format is the original one (timestamp in the first 26 characters, `<value> mm` positions); templates (`{time}`, `{x}`, `{y}`, `{name}` → `Measurement.name` for the name grouping, other fields → `Measurement.attributes`) or `re:` regexes with named groups. `identifier` (µs since datetime.min of `meas_time`) keys the cache rows and must be unique (`_read_data_dir` offsets equal times by 1 µs); the cache stores a hash of the files in identifier order (`_td_cache_key.txt`) and is rebuilt when it changes.
- `DataSet.transmission` corrects reference drift with `settings.pp_opt.ref_drift` (`RefDriftOpt`, off by default): `_drift_corrected_transmission` divides by the median of the reference's block (`_reference_blocks`) and interpolates geometrically to the block on the other side of the sample in time; `_raw_transmission` is the uncorrected one. `ImagePlot.real_grid_vals` applies `_destripe` (line offsets against a median trend) when `plot_opt.destripe` is on.
- `get_multi_data(meas_list, Domain)` returns arrays shaped `(n_meas, n_points, 2)` with `[..., 0]` the axis and `[..., 1]` the values. `avg_data_array` (`common/functions.py`) turns those into `[axis, mean, std]` columns.
- `DataSetFormatter` (base for plotters and evaluators) restricts data to its `freq_range` (`freq_axis`, `freq_range_idx`) and builds measurement → data dicts (`format_meas_dict`, which may include an `"Average"` key).
- Plotting: `common/dataset_plotter.py` — `DataSetPlotter`, `ExtendedDataSetPlotter`, `ImagePlot` (2-D raster images computed by `GridWorker` in a `QThread`, with sub-components `AverageValRect`, `SlicePlots`). `GridWorker` starts from a nan grid; `_grid_missing` (nan) pixels are 0 in `grid_vals` but masked (transparent) in `plot_image` and left out of the color limits (`_auto_cbar_limits`: percentiles, optionally centered on the median).

### Evaluation (material parameter extraction)
- `EvalComponentBase` (`common/eval_component/eval_component_base.py`) provides the worker count, transmission model and cost function selection, progress/cancel handling and result signalling (`EvalResultData` → `EvalResult` display + `ResultSaver`). Progress is for the whole run: `progress_start(total)`, `progress_set_total` / `progress_add_total`, `progress_advance`, `progress_stop(state)` (thread safe via Qt signals); the remaining time is extrapolated from the task rate since the first completed task. `QSpaceEval.run_scan` advances by `scan_task_count`, so callers put that into the total (`selection_task_count` for queues; the image evaluation estimates its total in `_update_progress_total`: the running scan, the expected follow-ups of the current level's untrusted window results, the coming levels' window pixels at the measured actual / nominal cost ratio (`_window_cost_ratio`, with a prior) and an outlier pass prior). The older `task_cnt_carrier` (0 reset, 1 advance, n new total) still drives `Regression`.
- `QSpaceEval` (`q_space_eval.py`) fits a transmission model to the measured transmission for a grid of (thickness d, time shift) tasks in a `ProcessPoolExecutor`, then picks the thickness that minimizes the "q-value" (Fourier amplitude of Fabry–Pérot oscillations remaining in the extracted n/k/alpha), optionally refining d iteratively. Worker functions must stay top-level and picklable: `spline_transmission_optimization` (`t_fit_global.py`, regularized cubic-spline n/k + `least_squares`) and `shgo_transmission_optimization` (`single_opt.py`, per-frequency SHGO); they get everything through a plain `config_dict`. `run_scan` submits them wrapped in `q_value.optimize_and_rate`, which also computes the q-value in the worker (`compute_q_value` with the plain dict from `QSpaceEval.q_value_params`) and drops datasets the caller doesn't keep. For the `tmm_1layer` model the workers use compiled numba kernels (`fast_kernels.py`: model, cost scan n guess, per-frequency Newton; same results as the numpy code) unless `eval_opt.spline_fit.use_compiled_kernels` is off or numba is missing.
- Transmission models (`transfer_functions.py`) have the signature `model(n, freq, **kwargs)` with kwargs `d`, `shift`, `n1`, `n4`, `nfp` (number of echoes, only used by the truncated echo models; and `n_sub`, `h` for two-layer models, marked by `layer_cnt_decorator`; `layers` for `tmm_multilayer`). They are evaluated independently per frequency and broadcast over array inputs (the spline Jacobian and the n-guess scan rely on this); `tmm_impl.coh_tmm_wrapper` is a vectorized transfer-matrix implementation. Models return the conjugated sample/reference ratio to match the measured phase convention.
- Multi-layer samples (`layer_stack.py`): `LayerStack` (sub-component "Multi-layer sample" of `QSpaceEval`) holds the layer list (`layers`, list of dicts, persisted) with exactly one unknown layer; with the `tmm_multilayer` model `build_context` passes `model_layers()` (propagation order, known n as constant or n(f) grid from a result file) as the `layers` model kwarg, and the FP estimates subtract the known layers' delay (`known_layer_delay`) and use the neighbouring indices for the echo amplitude.
- Initial refractive index guess (`n_guess.py`): time-of-flight estimate at a fixed thickness, or a per-task scan of the model cost.
- `ConductivityEval` (`conductivity_eval.py`): thin film on substrate conductivity, either the thin film (Tinkham) approximation with a bare substrate measurement as reference, or the exact two-layer model solved per frequency (complex Newton) with the air reference. It provides `QuantityEnum.Conductivity` to the image plot / regression through `DataSet.register_quantity_func`; components can provide other quantities the same way.
- Optional modules, each with its own switch: `common/visualization/` holds `TimeScans` (B-/C-scan) and `SpectralExplorer` (frequency slider, false-color RGB), sub-components of `ImagePlot` (toggles `en_time_scans`, `en_spectral_explorer`), `Spectrogram` (sub-component of `ExtendedDataSetPlotter`, `en_spectrogram`), `image_deconvolution` (applied in `ImagePlot.real_grid_vals` after destriping when `plot_opt.sharpen`; `ImagePlot.knife_edge_radius` from the last knife-edge fit) and `image_grid` (measurement values to the image grid, means per grid point). Matplotlib widgets (sliders, click handlers) only work while referenced: the components keep them in `_widgets`. `eval_component/dynamic_range.py` (`DynamicRangeOpt` = `eval_opt.dynamic_range`): `alpha_max` from the reference spectrum and the noise model's additive noise, added as dataset `alpha_max` in `QSpaceEval.prepare_results` and to `QSpaceImageEval.plot_pixel`; it imports the uncertainty module lazily (that imports the settings). `eval_component/effective_medium.py`: `EffectiveMedium` (AppRoot component, `en_effective_medium`; mixture / inclusion index, volume fraction fit vectorized over a fraction grid, `QuantityEnum.EMTVolumeFraction` from the q-space image pixels). Matching the reference of every measurement (`get_nearest_ref`, a Python loop over all references) is most of the time of transmission-based images.
- `SparseDeconvolution` (`sparse_deconvolution.py`): time-domain L1 deconvolution (FISTA with adaptive restart, FFT convolution, batched over traces) of the sample trace with its reference, optionally with the reference's Hilbert transform as second atom (group sparsity, complex peak amplitudes = phase-shifted pulses) and/or a self-calibrated pulse shape (transfer function of the strongest peak from a first pass; delay-dependent atoms via disjoint masks, echo k uses shape^(2k+1)); peaks of the impulse response give echo / interface delays, n and d (transmission: main pulse + first echo) or layer thicknesses (reflection). Peaks and derived values are stored in `SingleResultData.regression_params` so the result view shows them in its parameter table.
- Remote workers (`common/remote/`, settings `settings.remote` / `RemoteOpt` in `options.py`): `client.connect` starts `ssh -L <local port>:<unix socket> host python -c <BOOTSTRAP_STUB>`; the bootstrap reads a zip of the repo's .py files (`code_bundle`, cached per content hash in `~/.teval_remote/code/`) and the session authkey from stdin and runs `server.main` (process pool of `worker.run_task`, forkserver preloading the worker modules; tasks and results stay pickled bytes in the server process; exits on stdin EOF / client disconnect). `QSpaceEval.process_pool` uses `HybridExecutor` (remote + optional local `ProcessPoolExecutor`, FIFO dispatch by free slots, requeues tasks of a lost connection locally) when `active_connection()` is set; `worker_count` is local + remote. Host `"local"` runs the server as a local subprocess without ssh (tests). On Windows the server doesn't watch stdin: a thread blocked reading a pipe stalls starting the worker processes there. The server sets the BLAS / OpenMP thread variables to 1 before importing numpy (otherwise every worker starts a thread per core) and kills its process group on exit (the forkserver and its children aren't all in `pool._processes`). Results differ from local ones at rounding level (CPU-specific BLAS / numba code, also with the same package versions), which flips ~1-2 % of the image pixels (ambiguous minima); `setup_environment` pins the local package versions in a per-user environment (`client.user_venv`, `~/.teval_remote/venv-<local user>`; several people share the remote account); an empty `remote_python` means that one (`remote_python_path`), `migrate_config` maps the old shared `~/.teval_remote/venv` to it.
- Uncertainty (`uncertainty.py`, settings `eval_opt.uncertainty` / `UncertaintyOpt`): `UncertaintyEstimator` (one per dataset, `estimator_for`, cached for the references and `pp_opt`) fits the `NoiseModel` (additive + amplitude + timing jitter, median of consecutive reference differences) and the reference pulse series (`pulse_parameters`). `transmission_uncertainty(meas, refs, freq_idx, opt)` gives the `TransmissionUncertainty` of a mean transmission: per-frequency E|dT|^2 plus a timing / amplitude drift uncertainty (`drift_offsets` without the drift correction, `residual_drift` with it: leave-one-block-out prediction / sqrt 2, nearby blocks only, amplitude from unclipped blocks only). `perturbed_transmissions` draws the Monte Carlo samples. `QSpaceEval.mc_thickness_uncertainty` scans a window per sample (`replicate_optimum`: parabola vertex, moved windows) and returns `ThicknessUncertainty`; used by `eval_selection` (`d_uncertainty` in `optimization_info`, n / alpha `uncert`) and the image evaluation (`PixelResult.d_uncert`, `_uncertainty_impl`). `ConductivityEval._uncertainty` perturbs the film / substrate transmissions (drift drawn once for all film measurements) and thicknesses. Validated on the sapphire image (predicted vs actual pixel scatter); keep it validated against data when changing it.
- Phase convention: `dataset.transmission` and the transmission models' outputs are the complex conjugate of the e^{-iωt} physics convention (n = n' + ik with k > 0, sigma = sigma1 + i sigma2); conjugate before using physics formulas.

### Q-space evaluation workflow
Overview of how `QSpaceEval` and `QSpaceImageEval` (`q_space_image.py`, sub-component `QSpaceEval.image_eval`; it gets the `ImagePlot` via `QSpaceEval(dataset, image_plot=...)`. The scan building blocks shared by both, `ScanTarget` and `OptimizationCancelled`, live in `q_space_scan.py` so that `q_space_image` doesn't import `q_space_eval`) determine thickness d and refractive index n.

**Per measurement (selection)** (`QSpaceEval.eval_selection` → `run_scan`):
1. Context: the measured transmission on the fit range (`freq_range`). The Fabry-Perot round trip time comes from the group delay (`fp_round_trip_time`, at the mean of the thickness bounds). From that, the number of echoes visible in the time trace (`nfp`, if `auto_fp_count`) and the spline knot count (`knots_per_fp_period` knots per FP period, if `auto_knot_cnt`).
2. Task grid: one task per (thickness, shift) on `d_opt_axis_bounds` / `d_opt_axis_step` (shift axis only with `enable_shift_opt`), run in the `ProcessPoolExecutor`.
3. Each task (`spline_transmission_optimization`, d fixed):
   - Initial n: time-of-flight estimate, or the model cost scan per thickness (`n_scan_range`, `n_scan_step`, `k_scan_max`).
   - Regularized cubic-spline fit of n and k: `least_squares`, curvature penalty `reg_n` / `reg_k`, at most `max_nfev` evaluations, trust region subproblem solved by SVD or LSMR (`tr_solver`, the SVD of the Jacobian is otherwise the largest single cost of a fit).
   - Optionally (`per_freq_refine`), a per-frequency Newton solve started from the spline. It decides the final n, so the spline only has to land on the right branch: a few iterations (`max_nfev` ~5) give the same result as many.
4. q-value (`q_value.compute_q_value`, in the worker; `calc_q_val` for results computed elsewhere):
   - Fourier transform of the extracted n (or k / alpha, `q_space_quantity`) over frequency, optionally limited to the band where the FP echoes are above `fp_amp_threshold`.
   - q is the amplitude at the FP round trip time. A wrong d leaves FP oscillations in n, the correct d minimizes them.
   - Optionally (`eval_opt.q_value.remove_q_spikes`, off) isolated one-point spikes are replaced first (`remove_spikes`).
5. Optimum (`select_optimum`): the most prominent local minimum of q(d) (`prominent_min`), or the global minimum. With `iterative_thickness_optimization`, the grid is refined around it `iteration_count` times (shrinking by `bound_shrink_factor`).

**Image** (`QSpaceImageEval._evaluate_image_impl`): the same task per pixel (mean transmission of the pixel's measurements), with one shared context (one knot count / `nfp` for the whole image, so q-values are comparable between pixels).
1. Skip pixels without sample: |time of flight| below `min_time_of_flight` (air), and optionally a value range of any image plot quantity (`use_value_mask`, e.g. P2P for the opaque holder); `mask_erosion` rings next to those (`_masked_keys`) are skipped too (`_shrink_area`). The quantity "Q-space sample mask" in the image plot previews which pixels are evaluated. Pixel keys are grid indices divided by `pixel_binning` (`_pixel_key`), so binned blocks are one pixel; positions come from `_pixel_pos`, not the grid coordinates.
2. Probe pixels (`probe_pixel_count`): random pixels get the full thickness scan. The range of their valid results (q ≤ 2× median, not at a bound) plus `probe_range_margin` becomes the range of all later full scans. An optimum at that range's edge triggers a scan of the full configured range.
3. Coarse to fine levels (`seed_stride`):
   - Seed pixels get a full scan.
   - Every further pixel only scans a window (`nbr_d_window`, `nbr_d_step`) around the median thickness of its evaluated neighbours.
   - A window optimum at the window edge moves the window (`max_window_shifts`). A q-value above `max_q_ratio` × the neighbours' (e.g. a thickness step) falls back to a full scan.
4. Interpolated minimum (`interpolate_minimum`): instead of refinement iterations, one extra fit at the vertex of the parabola through the best grid point and its two neighbours.
5. Outlier passes: pixels deviating from their 8 neighbours by more than max(`outlier_threshold`, 3× the neighbours' robust scatter) get a window scan around the consistent neighbours. The new result is only kept if it is trusted.
6. Results (`PixelResult`: d, shift, q, n, full scan flag, q(d) profile of the last scan and its `minimum_width`) are provided to the image plot / regression as the `QSpace*` quantities via `DataSet.register_quantity_func` (also band means of n / alpha over `band_range`). `_results_arrays` holds everything for the `.npz` ("Save image results", the autosave in `_run_targets` / at the end of `_start`, "Load image results" → `_load_results`): pixel results with nan-padded profiles, run pixel / skipped keys, `_run_info`, settings JSON (`common.settings.component_settings`) and `code_version()`. "Continue evaluation" (`_continue_impl`) and "Re-evaluate area" both go through `_evaluate_pixels` (adds to the existing results). Untrusted window results are stored until their follow-up scan replaces them (`_provisional`); continuing after a cancel evaluates those pixels again.
7. Reliability (`pixel_confidence`, computed on demand from the stored results): minimum width relative to the median of the image, q-value and thickness relative to the 8 neighbours (the same deviation limit as the outlier passes, `_deviation_limit`). Clicking a pixel of a Q-space image (`ImagePlot.click_handlers`) calls `plot_pixel` (q(d), n, alpha with the neighbours). "Re-evaluate area" / "Re-evaluate inspected pixel" rerun the level scan (`_scan_levels`) or a full scan for some pixels, with the echo and knot count of the image evaluation (`_run_info`) so the q-values stay comparable.

Cost: almost all time is spent in the worker fits (~30 ms per fit and core with the compiled kernels, LSMR and `max_nfev` 5, single-layer model); the main process only unpickles results and keeps the books (~1 ms per result, busy about a third of the time with 8 workers). Without the compiled kernels the n-guess cost scan, the spline fit and the Newton refinement take comparable time once `n_scan_range` is limited to the plausible range and `max_nfev` is small; with LSMR the spline fit's SVD is avoided. A pixel's thickness can't be interpolated from its neighbours: the neighbour prediction is off by ~3 µm (median), much more than the run-to-run repeatability (~0.4 µm). The neighbours only steer the scan window. A thickness fit with one shared n(f) from the reliable pixels was tested and rejected: n varies by ~0.02 between pixels, which gives ~20 µm thickness errors with a fixed n, and fitting an n offset per pixel is degenerate with d (only (n-1)·d is well determined).

### Units
Internal magnitudes use µm for lengths, ps for time, THz for frequency, 1/cm for absorption coefficient, S/cm for conductivity; `c_thz` (µm/ps) and `eps0_thz` are in `common/consts.py`. Shift values are in fs (converted inside the models).
